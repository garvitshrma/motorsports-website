# TEAM AGNISHUL — IIT Bhilai Motorsports

Complete redesign of the team site. Industrial motorsport × neubrutalism: thick
rules, hard block shadows, oversized condensed display type, blueprint underlays
and a restrained ink / paper / grey palette with racing red used only for
accents, active states and figures that matter.

Stack: **React 19 + Vite 7 + React Three Fiber + drei + three + Framer Motion**,
hand-authored CSS (no utility framework — the layouts are too editorial for one).

```bash
npm install
npm run dev      # http://localhost:5173
npm run build
npm run preview
```

## Logo

The supplied artwork is a 3.5:1 lockup on an opaque white background with black
"IIT BHILAI" lettering. Two files are generated from it into `public/images/`:

| File | What it is |
| --- | --- |
| `logo.png` | White knocked out, **colours untouched** — for light grounds |
| `logo-dark.png` | Same, but the black lettering and car outline remapped to off-white so they read on the dark navbar and loader. **The red is untouched.** |

The white is removed by un-multiplying against the background rather than
thresholding, so the antialiased edges keep their true colour instead of going
grey. Both are wired through `team.logo` / `team.logoLight` in
[`src/data/site.js`](src/data/site.js).

The loading screen spins the wheels, which needs the mark split into layers:
`logo-dark-base.png` (the logo with both wheels lifted out) plus
`wheel-front.png` / `wheel-rear.png` as square, hub-centred sprites. Three
things make that spin cleanly rather than wobble:

- **Hub centres are found, not guessed.** The hub is a solid disc sitting inside
  an empty gap ring; the script scores candidate centres on that local
  signature, which lettering overlapping the tyre further out cannot skew. The
  tyre edge then comes off the angular-coverage profile. A sprite centred
  anywhere else orbits instead of spinning.
- **Rods and tubes are rejected.** A wheel is rotationally symmetric; the
  suspension arms crossing it are not. A pixel only joins the sprite if the same
  spot is covered at most other rotations too, so rods stay on the static base
  plate — which is correct, they are bolted to the car.
- **Occlusion is repaired, and the rear reuses the front.** Lettering is drawn
  over both tyres, so a lifted sprite has a bite missing that would rotate as a
  hole. Missing arcs are rebuilt from the rest of the ring. The rear wheel is so
  heavily covered by the "P" that rebuilding it leaves streaks, so it reuses the
  front sprite — the same drawing at the same size. Its own pixels are still
  lifted off the base, so nothing doubles up.

In the page the wheels sit **below** the base plate (`z-index`), so lettering,
shocks and chassis always draw on top of whatever is spinning underneath.

Everything above is regenerated by one script, so the artwork stays editable:

```bash
pip install Pillow
python tools/prepare-logo.py path/to/original-logo.png
```

It prints the `team.logoWheels` offsets to paste into `src/data/site.js`, and
writes `logo-spin-preview.png` in the project root showing the wheels at 0/40/80
degrees — check that nothing except the wheels moves between the three. If you
change the artwork, re-check the hub coordinates at the top of the script.

The navbar shows the lockup on its own — the mark already carries "MOTORSPORTS
IIT BHILAI", so the old text wordmark beside it would have been a duplicate.
`favicon.png` / `apple-touch-icon.png` are the buggy alone on racing red; the
full lockup is unreadable at tab size.

If you would rather not have a recoloured variant, set `team.logo` to
`/images/logo.png` and give `.nav__logo` and `.loader__logo` a paper-coloured
plate behind them instead.

## Loading screen and page transitions

**First load** shows a full-screen loader ([`src/components/Loader.jsx`](src/components/Loader.jsx)):
the logo drives in from the left, red speed lines sweep beneath it, and the mark
lights up left-to-right as a clip mask tracks real progress — alongside a red
bar and a 000–100 counter. Four shutters then lift away like a garage door.

Progress is genuine, not faked. The 3D chunk reports loader progress through a
tiny shared bus ([`src/lib/boot.js`](src/lib/boot.js)) so the main bundle never
has to import three.js just to show a percentage. Two guards matter:

- **The bar only ever moves forward.** three's loading manager reports
  `loaded / total`, and `total` grows as new items are queued — so when the
  `.glb` finishes and its textures are added, the ratio drops back down and the
  percentage runs backwards. Progress is now a high-water mark in
  `boot.js`, with a second monotonic guard in the loader for the
  document-ready step.
- `MIN_MS` (1.6s) — the counter is rate-limited so it always counts up, even
  when everything is already cached, instead of snapping to 100.
- `MAX_MS` (5s) — an absolute cap. A large car model must never hold the whole
  site hostage; past this point the site appears and the car arrives on its own
  in the hero. A `setInterval` plus a backstop `setTimeout` drives it rather
  than `requestAnimationFrame`, which browsers pause entirely in background
  tabs — that would otherwise leave a frozen loading screen.

**Route changes** fade the old page out and the new one in (~0.3s), with a red
bar sweeping under the navbar. Both honour `prefers-reduced-motion`, which drops
straight to an instant swap.

## The 3D car

Drop the team's model at:

```
public/models/car.glb
```

The shipped `car.glb` is **optimised to 1.9 MB** (down from 106 MB). Textures
were the whole problem — 88 MB of the original was PNG/JPEG maps, against only
17 MB of geometry.

Re-run the pipeline after replacing the model (`@gltf-transform/cli` is a
devDependency):

```bash
npx gltf-transform optimize <source>.glb public/models/car.glb   --compress meshopt --texture-compress webp --texture-size 1024 --simplify true
```

| Step | Effect |
| --- | --- |
| `--texture-compress webp --texture-size 1024` | 88 MB of PNG → 0.7 MB of WebP |
| `--simplify true` | 329k → 136k triangles |
| `--compress meshopt` | quantises and packs the remaining geometry |
| (join/dedup) | 16 meshes → 5, so fewer draw calls |

All three extensions it writes — `EXT_meshopt_compression`, `EXT_texture_webp`
and `KHR_mesh_quantization` — decode **without a CDN**: drei wires three-stdlib's
`MeshoptDecoder` by default, and three handles the other two natively. Draco was
deliberately avoided because drei fetches its decoder from a Google CDN.

Raise `--texture-size` to 2048 if the car looks soft on large displays; it costs
little now that the maps are WebP.

> The original 106 MB asset is still in git history if you need it back
> (`git checkout 3697b8e -- public/models/car.glb`). `public/models/` also holds
> unreferenced `car2.glb` (16 MB) and `car3.glb` (25 MB) — everything in
> `public/` ships whether the code imports it or not, so those 41 MB are still
> in every deploy.

Nothing else needs to change. The site detects the file at runtime and swaps
from the fallback drawing to the live scene.

**Geometry is never modified at runtime** — the model is only centred, seated on
the ground plane, and uniformly scaled so its longest horizontal axis is a known
size, which keeps framing consistent whatever units the export used.

That normalisation lives in [`normaliseModel`](src/three/normaliseModel.js) and
is deliberately **idempotent**: it resets the transform before measuring.
`Box3.setFromObject` reports world-space bounds, so measuring a model that has
already been scaled folds the old scale into the new one — and React StrictMode
runs layout effects twice on every mount. That shipped once as "the car is
sometimes small, sometimes big", alternating between the right size and double
it. The offsets are also multiplied by the scale, since three applies
translation in parent units, outside the scale.

All tuning lives in [`src/three/carConfig.js`](src/three/carConfig.js):

| Setting | What it does |
| --- | --- |
| `MODEL_URL` | Path to the asset |
| `TARGET_LENGTH` | World size the car is normalised to |
| `BASE_YAW` | Resting angle (default is a 3/4 front view) |
| `SCROLL_YAW` | How far it rotates toward profile as the hero scrolls away |
| `PITCH` / `ROLL` | Corrections if the export is not Y-up |
| `OFFSET` | Nudges the car off the layout centre |
| `POINTER_YAW` / `POINTER_PITCH` | Cursor response (kept restrained) |
| `PLAY_CLIPS` / `CLIP_NAME` | Animation clips — see below |
| `CAMERA.*` | Framing, dolly and sway |

If the `.glb` ships animation clips they are **inspected but not played**. Their
names are logged to the console on load (`[CarScene] clips available…`); set
`PLAY_CLIPS: true` (optionally with `CLIP_NAME`) once you have checked that a
clip actually improves the shot rather than fighting the scroll choreography.

### Rendering

- Lighting is a pit-garage setup: hard key from high front-left, cool rim behind
  to carve out the silhouette, low warm fill. Reflections come from a
  procedurally generated `RoomEnvironment` — **no external HDR download**.
- `ContactShadows` ground the car so it doesn't read as a floating render.
- Tone mapping is ACES Filmic.

### Performance and fallbacks

The whole three.js stack is a **lazy chunk** — it is not fetched until the stage
scrolls into view, so the rest of the site paints without it.

`src/components/CarStage.jsx` decides what to render:

| Condition | Result |
| --- | --- |
| Desktop, WebGL, model present | Full scene: shadows, DPR ≤ 2, antialiasing |
| Narrow screen / ≤ 4 cores | Reduced: no shadow maps, DPR ≤ 1.5, single-frame contact shadow |
| `deviceMemory` < 4, or no WebGL | Scene skipped entirely |
| `car.glb` missing | Technical side-elevation drawing |
| Scene throws at runtime | Error boundary inside the Canvas swaps to the drawing |

The frame loop is also suspended (`frameloop="never"`) whenever the stage is off
screen, and scroll and pointer values are held in refs so neither ever triggers a
React re-render.

The fallback is a real drawing ([`src/three/VehicleDrawing.jsx`](src/three/VehicleDrawing.jsx)),
not a stand-in 3D object — an unfinished spec sheet is honest in a way a grey box
is not. It is also reused as the watermark on the recruitment section and 404.

## Circuit rail and chequered flag

**[`TrackNav`](src/components/TrackNav.jsx)** is the page navigation drawn as a
circuit: a winding tarmac path with a racing line, a numbered node per page, and
a white marker that runs from the current node toward the next one as you scroll.

Node positions are *measured* off the SVG path with `getPointAtLength`, not
hard-coded — edit the `TRACK` path string and the nodes follow it. The nodes are
drawn **inside** the SVG rather than as positioned HTML over it: an HTML overlay
has to express path coordinates as percentages of the container, which only
agrees with the drawing while the container's aspect ratio matches the viewBox.
Any other shape and `preserveAspectRatio` re-centres the artwork, leaving the
nodes floating beside the track. It is fixed to
the right edge and appears only at 1340px and up; above that breakpoint `.shell`
(and the two full-bleed strips) reserve `--rail-w` on the right so nothing ever
sits underneath it. The top navbar stays the primary navigation at every size.

**[`RaceFlag`](src/components/RaceFlag.jsx)** is the chequered pennant. The cloth
is one SVG path filled white and *stroked* with a chequer pattern — that gives
the banded border without hand-building an inset outline. The whole cloth group
runs through a turbulence displacement filter whose frequency is animated, so it
ripples like fabric rather than just swaying, and the logo inside the group
ripples with it. It uses `logoLight` (the original colours), since the flag field
is white.

Both honour `prefers-reduced-motion`: the ripple filter and sway are dropped, and
the rail's transitions stop.

## Legibility

Small print is the easiest thing to get wrong on a dark, high-contrast layout,
so colour and type size are both driven by tokens rather than set per component:

- `--grey` / `--grey-d` / `--grey-l` are defined for the **ink** ground and
  redefined inside `.on-paper`. The old `--grey-d` was 2.4:1 on `#0b0b0b` — far
  under AA — which is why so many labels were hard to read.
- `--red-text` is a separate token from `--red`. The brand red clears neither
  ground as small text (3.96:1 on ink, 4.21:1 on paper), so text uses a brighter
  red on ink and a darker one on paper. Bars, fills and borders keep `--red`.
- No text renders below ~10px; the mono label scale sits at 0.7–0.74rem.

Every text node on every route was measured against its own computed background:
**0 failures** at AA (4.5:1 for body, 3:1 for large).

## Spacing

Whitespace is driven by a few tokens rather than per-component values, so it can
be opened up or tightened in one place:

- `--gut` — the page gutter, `clamp(22px, 5vw, 88px)`
- `--rail-w` — right-hand gutter reserved for the circuit rail
- `.sec` vertical rhythm, `clamp(92px, 11.5vw, 210px)`

## Content — please read

**All copy comes from the existing site** (`iitbh-fi.vercel.app`) and lives in one
file: [`src/data/site.js`](src/data/site.js). No team members, results, dates,
sponsors or statistics have been invented.

The copy has been cut back hard — sub-pages run 50–80 words each — and technical
jargon ("dispatch", "registry", "survival cell", "REQ. FORM 01") has been
replaced with plain words. Nav labels are now simply Home / Cars / Team /
Sponsors / Gallery / News / Contact. Shortening removed words, never facts.

A number of values on the current live site are themselves unfilled template
defaults. Rather than dress those up as facts, they are carried across and
**flagged**:

```js
{ name: null, role: 'TEAM LEAD', tbc: true }
```

Anything marked `tbc: true` renders with a visible red **TBC** marker, and empty
fields render as `POSITION OPEN` / `AWAITING NAME` rather than filler. Grep for
`tbc` to find every outstanding item. The current list:

- **Crew** — only `DURGANSH MISHRA (SECRETARY)` is confirmed. Team Lead,
  Technical Head and Design Head are unnamed on the source site.
- **Subsystems** — the site publishes "4 subsystems" but never names them. The
  count shows as a stat; the grid of four empty boxes was removed as noise. The
  `subsystems` array is still in `site.js` to re-add once they have names.
- **Vehicles** — `CAR1 / CAR2 / CAR3` and their specs (V8 twin-turbo, 380 km/h,
  "Racing Division Alpha") read as template defaults. Every spec is marked TBC.
- **Sponsors** — all twelve names are placeholders across three tiers. Rather
  than twelve separate markers, one line says so (`sponsorsArePlaceholder`).
- **Contact** — `team@agnishul.com`, `email@iitbhilai.ac.in` and
  `+91 XXX XXX XXXX` are placeholders; all social links point at `#`.
- **Competitions count** on the vehicles page is not published anywhere, so it
  renders as `—`.
- **Gallery** — captions are real, images are not published. Set `src` on any
  entry in `gallery` to a file in `public/images/` and that tile renders the
  photograph instead of a placeholder plate.

Confirmed content carried over unchanged: the 2010 / 2015 / 2020 / 2024 timeline,
the three pillars (cars / team / mission), all three news entries, the campus
address, and the 4 subsystems / 30+ engineers / 1 shared vision figures.

## Structure

```
src/
  components/     Navbar, Footer, PageHead, CarStage, ui primitives
  sections/       Home sections — Hero, About, Engineering, Journey,
                  Achievements, PartnersStrip, Join
  pages/          Routed pages — Home, Vehicles, Crew, Partners,
                  Archive, Dispatch, Contact, NotFound
  three/          carConfig, CarScene, CarModel, VehicleDrawing
  data/site.js    ALL content
  styles/base.css Design tokens, reset, type scale, primitives
  lib/            usePageTitle
```

The home page is deliberately short — hero, the three pillars, and the timeline.
The Engineering, News, Sponsors and Join sections were removed from it at the
team's request; their components still exist under `src/sections/` (unimported,
so they add nothing to the bundle) if you ever want them back. News and sponsors
remain on their own pages.

Routes preserve the original URLs (`/cars`, `/team`, `/sponsors`, `/gallery`,
`/news`, `/contact`) so existing links keep working.

**News is no longer in the navigation** (nor the footer, nor the home page). The
`/news` route and its page still exist and still render, but nothing links to
them any more — delete `src/pages/Dispatch.jsx` and its `<Route>` in `App.jsx`
if you want it gone for good.

`vercel.json` adds the SPA rewrite the current deployment is missing — today
`iitbh-fi.vercel.app/team` returns a 404 on direct load.

### Design system

Tokens and primitives are in `src/styles/base.css`. The useful ones:

- `.display` + `.d-xxl … .d-sm` — condensed 900-weight headline scale
- `.slab` / `.plate` — bordered blocks with offset shadows (ink and paper grounds)
- `.eyebrow`, `.tag`, `.tbc`, `.racenum` — technical labelling
- `.blueprint`, `.metal`, `.ruler`, `.hazard` — surfaces and markings
- `.sec--ink` / `.sec--paper` — the alternating section grounds

Type is one superfamily plus a mono: **Archivo** (variable width axis, run at 62%
width / 900 weight for display) and **JetBrains Mono** for technical labels.

## Contact form

There is no backend. `FORM_ENDPOINT` in
[`src/pages/Contact.jsx`](src/pages/Contact.jsx) is `null`, so the form composes a
message in the visitor's own mail client and says so on the page rather than
pretending to send. Set it to a form service or API route and it POSTs JSON
(`name`, `email`, `subject`, `message`) instead.

## Accessibility

Skip link, focus-visible outlines, labelled form fields, `aria-*` on the mobile
nav and filters, 44–48px minimum touch targets, and `prefers-reduced-motion`
honoured — reveals, counters and the marquee all stop.
